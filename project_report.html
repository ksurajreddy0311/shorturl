Secure URL Shortener with Threat Detection
Full-Stack Academic Project Report & Technical Reference
Domain: Web Development, Cybersecurity & Cloud Computing • Stack: HTML, CSS, JavaScript, Python (Flask), Google Cloud Firestore Ready

1. Executive Summary & Problem Statement

Uniform Resource Locator (URL) shorteners are widely utilized to transform lengthy web addresses into compact, shareable tokens. However, conventional public shorteners blindly redirect users without destination verification, making them frequent vectors for cyber attacks, specifically phishing campaigns, credential harvesting, and malware delivery.

This project introduces a security-oriented URL shortener. In addition to core URL shortening and analytics, the system incorporates an integrated threat detection engine that automatically analyzes destination URLs for deceptive heuristics, validates transport protocols, and halts suspicious redirects with an intermediate security advisory page.

3. Backend Function Specifications (`app.py`)

is_valid_url(url: str) -> bool

Performs input validation and sanitization using urllib.parse. Strictly enforces http:// or https:// schemes, rejecting hazardous URI schemes such as javascript: (Cross-Site Scripting) or file:.

inspect_url_security(url: str) -> (bool, str)

The core cybersecurity module. Evaluates destination URLs against four heuristic rules:

  • Raw IP Hosts: Uses regular expressions (IPV4_REGEX) to flag direct IP address hosting commonly used in malicious servers.
  • Phishing Keywords: Scans against suspicious patterns including claim-reward, free-crypto, and banking-login.
  • Suspicious TLDs: Evaluates domain endings against high-risk top-level domains frequently abused in spam campaigns (e.g. .tk, .xyz, .buzz).
  • Obfuscation: Detects the presence of @ symbols in network locations used to obscure true destinations.

generate_short_code(length: int = 6) -> str

Generates unique alphanumeric tokens (using string.ascii_letters + string.digits) and verifies uniqueness against the database to guarantee collision resistance.

shorten_url() • POST /api/shorten

REST API receiving JSON payloads, invoking validation and security scans, persisting link metadata, and returning short URL responses.

redirect_to_url(short_code) • GET /r/<short_code>

Handles link redirection. Atomically increments the click counter. For safe links, performs an immediate HTTP 302 redirect. For flagged links, halts navigation and renders an intermediate Safety Advisory page.

4. Cloud Computing Integration

Cloud computing transforms this local application into a globally available, enterprise-grade web service. It fulfills three primary responsibilities:

  • Cloud Hosting / Compute (Vercel / Google Cloud Run): Provides 24/7 serverless execution environments. The application is hosted on globally distributed container infrastructure, guaranteeing continuous uptime without relying on personal hardware.
  • Cloud Database (Google Cloud Firestore): Replaces volatile in-memory storage (RAM) with a scalable, multi-region NoSQL document store. Persists link mappings, security flags, and real-time click metrics with automated backup and low-latency global replication.
  • Traffic Elasticity & Auto-Scaling: Dynamically allocates computing resources during peak traffic surges and scales down to zero when idle, ensuring maximum cost-efficiency and resilience against traffic spikes.

6. Viva / Defense Q&A Quick Reference

Q: Why does the system flag links rather than blocking them outright?
A: Heuristic detection can encounter false positives. Following industry standards (e.g. Google Safe Browsing), the system flags potential risks and serves an interstitial advisory screen, informing the user while allowing informed manual progression.
Q: Where is cybersecurity enforced: client-side or server-side?
A: Exclusively server-side in app.py. Client-side validation can easily be bypassed by intercepting or replaying HTTP requests. Enforcing validation in the Python backend guarantees zero-trust input handling.
Q: What is the benefit of Firestore over relational databases (like MySQL) for this project?
A: Firestore provides serverless scaling, document-level read/write optimization for short-code lookups, native JSON integration with Flask, and eliminates traditional database administration and connection-pooling overhead.
